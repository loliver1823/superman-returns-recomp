R1 batch 1 - L6 golden_call cases (archive/r1/l6/b1.script): what each case exercises
=====================================================================================
47 cases over 21 of the 24 functions. Every case runs on the old splice body and on the hooked
pristine body; registers and changed-page hashes must match.

Shared fixtures (written by W inside each case that needs them; memory is restored at END)
- Stub targets in .text (mapped recompiled functions, no kernel override):
  NOP 0x8213C3A0 (blr), RET0 0x8213C3A8 (li r3,0; blr), RET1 0x8213C3C8 (li r3,1; blr).
  BAD = 0x00001000 / 0x00002000 / 0x00003000: an indirect-call target outside .text.
- FREE SINK: DogmaFree (sub_8278D3C0) looks up the owning heap in the table *0x829A9424
  (count *0x829A93F0). The cases point it at one scratch entry {heap 0x70D00100, 0x70000000,
  0x70E00000} whose vtable+0x2C is RET0, so freeing any scratch pointer is a no-op. Without it a
  scratch pointer has no owner and DogmaFree calls through *(*(0)+0x2C).
- ALLOC SINK: DogmaAlloc (sub_8278D258, r5=0) misses the per-thread registry (count
  *0x829A93EC forced to 0), takes the fallback pool *0x829A93F4 = 0x70D01000 whose vt+36 is
  sub_826E5848 (returns *(0x829A242C)), so every allocation returns the block written to
  0x829A242C. It still runs ThreadGetCurrentHandleCached (KeTlsGetValue / NtDuplicateObject,
  both provided by the harness). sub_8278D258 carries a band-aid override whose grant
  substitution needs SR_ALLOW_FORCING; the harness must run with forcing off.
- FAKE RESOURCE MANAGER: sub_826E5838 returns *(0x829A2434); the cases set it to 0x70C80000
  with vtable 0x70C80100 (vt+32 and vt+40 chosen per case).

Harness assumptions to check when running
- Guest memory the golden dump does not map (scratch 0x70000000.., page 0) reads as zero and
  is writable. Two FIRE cases touch page 0 in BOTH bodies because the forced path itself does:
  sub_820F0048_fire_bufptr0 (the unguarded tail sub_820F0208 stores 4 words at VA 4..0x13) and
  sub_82187460_fire_vt32_outside_text (AptHandleAssignLocked reads *(0) through the faked r3=0).
- sub_8218F890_fire_scan_200000_empty and sub_821DDD18_fire_100000_elements rely on large
  zero scratch ranges (0x70200000..0x702C3510 and 0x70000000..0x70927D00) not written by W.

Functions without a case (cannot be called standalone)
-----------------------------------------------------
sub_82151560 FMGameRender_ModuleInit: the render-module init. Before either guarded bctrl it
  runs the render/scene subsystem constructors (sub_822EABA0, sub_822F72E0, sub_822E4B58,
  sub_822E4C10 on *(0x82970140)), and between the two sites it builds the world/render managers
  (sub_82779BE0, sub_82721AE0, sub_827770B8, sub_82775BC0, sub_822EED40, sub_82187678, a
  104-byte DogmaAlloc + sub_8215ED90, sub_8219FFE8, sub_822D7B60). That is device/subsystem
  creation with imports the harness does not provide; it cannot run against a golden snapshot
  that already holds the initialised objects. The two hooks are the same out-of-.text guard
  as sub_8214AFB8 / sub_82318FB0, whose cases prove the shape.
sub_821516E0 FmuiGlobalInit: the 563-instruction FMUI global init (57 direct calls: the Apt
  flow manager factory sub_826D4D60, allocations and subsystem constructors before the guarded
  vt[4] call at 0x82151E2C). Same reason; same guard shape as above (plus the dead lr, see the .cpp).
sub_8229F460 (video-out / net init): a constructor that allocates (sub_8278D258 272 bytes,
  sub_8278D530), runs subsystem inits (sub_821680B0, sub_82162EA8, sub_825F7AF0, sub_82604250,
  sub_82722600, sub_82722A80, sub_82721C88, sub_827220E0 x4, sub_82565B70) and then polls the
  'conn' dispatcher against a wall-clock deadline (sub_82564E80 is a kernel override reading
  the host clock; sub_82564FC8 waits). Not standalone, and the loop exit is time-dependent.
  The cap/reset hooks are the same per-call-counter shape as sub_821DDD18 and sub_8218F890.
