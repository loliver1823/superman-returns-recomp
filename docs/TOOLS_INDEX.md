## The rule

1. **Every tool lives in git, in this repo, under `tools/`** (or `scripts/` for the repo
   gates). Not in a lane's `archive/v1_*` folder, not in a worktree-only branch, and not in
   another workspace such as `the owner's private mod project`.
2. **Promote lane-local scripts before the lane closes.** If a lane script will be needed
   again, fold it into the canonical tool for its job (table below) or add it under `tools/`
   with a usage header. Then merge. The `archive/v1_*` copy stays as provenance. A lane
   that re-invents `roll.ps1`, `press.py` or `sheet.py` should extend the canonical one.
3. **Asset DATA stays outside git.** Rips, extracted disc bytes, research dumps, built packs,
   and reports that carry asset hashes or paths live in the asset work folder
   (`SR_ASSET_WORK`, default `<asset work folder>`). Run artifacts go to `archive/`
   (gitignored). The code that reads that data lives in `tools/assets/` and finds it through
   `tools/assets/paths.py`.
4. **Background-run rules apply to every launcher** (TOOLKIT 1.8a). Hold the game slot
   (`tools/game_slot.py`), launch through `sr_drive.ps1`, `Start-SrGameProcess` or
   `bg_window -BgLaunch`, set `SR_INSTANCE_ID`, send input only on the harness channel, and
   stop only the process you started.
